# DM-MC02 QEMU current capability and evidence matrix

Audit date: 2026-10-01. This is the canonical statement of current QEMU
capability. `ARCHITECTURE.md` defines design invariants, `INTERFACES.md` defines
the detailed contracts, and `PLAN.md` defines ordered future work. Historical
checklists and reports remain evidence for their dated revisions; they do not
override this matrix.

Current worktree validation is recorded once in [PLAN.md](PLAN.md).
The 2026-09-29 frozen engineering package and its independent-build/RTF
identities are recorded in the [release report](reports/2026-09-29-engineering-release/README.md)
and its validation sidecar. Later source changes do not inherit that package
identity. Earlier gate histories remain in their dated reports, not here.

The 2026-10-01 NOR adapter simplification removes its single-choice type
parameter, duplicate size cache and initialization identity probe. Admission
still rejects wrong geometry/ID before realization; real SSI tests own wire
identity verification. This changes no device capability status.

## Status vocabulary

| Status | Meaning |
| --- | --- |
| `supported` | The named, bounded contract has isolated and direct-consumer evidence in the canonical gate. It does not cover behavior listed under limits. |
| `approximation` | The path is implemented and tested, but deliberately simplifies timing, electrical, physical, or protocol behavior. |
| `fixture` | Test-only support. It is not a production board or product capability. |
| `unsupported` | The project deliberately does not provide this capability at present. |
| `unverified` | Some implementation or historical evidence exists, but the required current integration or physical evidence is missing. |

Status applies only to the boundary named in its row. For example, a
`supported` register/data-path subset does not make the complete STM32H723
peripheral silicon-accurate. Test counts are dated denominators, not a project
completion percentage.

## Explicit non-claims

- The matrix does not claim a complete STM32H723, cycle-accurate buses,
  electrical signal integrity, full USB host/device behavior, CAN physical
  timing, or a calibrated BMI088/motor/plant.
- Component VMState and migratable RAM blocks do not imply DM-MC02 machine
  snapshot or live migration.
- A ROS2 adapter does not imply Gazebo integration, and a MuJoCo smoke does not
  imply a Release-firmware closed loop.
- `stm32h723-usb-host`, NullEngine, local CAN medium, local NOR framing and the
  v2 motor loopback remain fixtures. They cannot be used as board capability
  evidence.
- Renode is outside the current implementation and acceptance scope. `trobot/`
  remains an unmodified external firmware input.
